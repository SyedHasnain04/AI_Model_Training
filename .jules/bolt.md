## 2024-05-19 - [Pixel-value-to-label mapping in masks]
**Learning:** Found a performance bottleneck in `convert_mask` where pixel-to-label mapping was done sequentially via multiple boolean array masking operations. This was very inefficient, running in O(N * C) where N is pixels and C is number of classes. Using a NumPy lookup table (LUT) approach maps labels in a single pass O(N) by using pixel values as indices.
**Action:** When performing pixel-value-to-label mapping in masks, use a NumPy lookup table (LUT) cached as a function attribute instead of multiple boolean mask assignments for better performance. Ensure bound safety by using `np.where((arr >= 0) & (arr <= MAX_VAL), arr, 0)` before indexing the LUT to safely map out-of-bounds values to 0 (background) and prevent `IndexError`s.
